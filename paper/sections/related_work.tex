\paragraph{Orbital edge computing and LEO networking.} Moving computation to the network edge is old news in terrestrial systems; OEC is the same idea where the edge is the satellite, motivated by a downlink that's orders of magnitude smaller than what a modern sensor can capture in one pass. LEO adds something terrestrial edge computing mostly doesn't have: the topology isn't just variable, it's \emph{predictable} -- satellite and ground-station positions, and therefore contact windows and candidate routes, come straight out of orbital mechanics. The simulation environment here is built on Hypatia~\cite{kassing2020hypatia}, which models constellation geometry, ISLs, and ground-station contact windows explicitly. That's what makes a scheduler that predicts near-term connectivity, instead of just reacting to it, both possible and testable at this scale.

\paragraph{Learned compression for downlink-constrained systems.} Compression here uses a residual-quantized VAE~\cite{lee2022autoregressive}: an encoder maps an image to codebook indices, and successive residual-quantization stages refine the reconstruction, each one correcting what the last stage got wrong. How many stages you run before transmitting -- depth, in this paper's terms -- is exactly the fidelity/payload knob a scheduler has to reason about. We evaluate it on two remote-sensing datasets: EuroSAT~\cite{helber2019eurosat} (10-class land-cover classification, used for an initial spatial-size/depth sweep) and FLAIR-1~\cite{garioud2022flair} (aerial imagery, 15-class semantic segmentation, the dataset behind this paper's central downstream-task result). Most learned-compression papers stop at pixel-fidelity metrics -- PSNR, SSIM, LPIPS, FID -- as the end goal. This paper treats them as necessary but not sufficient: \S\ref{sec:downstream} shows they can sit nearly flat exactly where a downstream task's performance doesn't.

\paragraph{MPC-based scheduling.} Model Predictive Control -- plan over a finite horizon, act on only the first step, replan as new information arrives -- fits a system whose future state is partly predictable (contact windows) but still genuinely uncertain (bursty arrivals, imperfect forecasts). We keep the scheduling problem a mixed-integer linear program so it stays solvable at the sizes this paper tests, and build a piecewise-linear coverage reward specifically so a concave objective can be optimized without adding binary or SOS2 variables (\S\ref{sec:coverage}) -- a standard trick for keeping a nonlinear objective inside an LP's reach. We compare this against simpler greedy baselines, a learned policy (\S\ref{sec:rl}), and hierarchical/peer couplings that split routing and depth into separate optimizers (\S\ref{sec:formulation}).
